# AI 报告草稿与签到失败邮件提醒

这两项都是可选功能，部署者使用自己的服务与凭证。社区源码、示例配置和前端构建不附带真实密钥。

## 配置 AI 服务

在服务端环境变量或本地 `.env` 中填写以下三项，均无默认值：

```dotenv
REPORT_AI_BASE_URL=
REPORT_AI_MODEL=
REPORT_AI_API_KEY=
```

`REPORT_AI_BASE_URL` 是支持流式 Chat Completions 的 HTTPS 基础地址，例如 `https://your-provider.example/v1`；程序在其后追加 `/chat/completions`。地址不能包含用户名、密码、查询参数或片段。`REPORT_AI_MODEL` 使用服务商提供的模型名，`REPORT_AI_API_KEY` 使用你自行申请的密钥。程序不会跟随携带认证信息的重定向。

默认从服务工作目录的 `.env` 读取这三项，也可通过服务端进程环境变量覆盖；环境变量为空时也会覆盖文件值。使用 `REPORT_AI_CONFIG_FILE` 可指定独立的本地配置文件。配置按请求读取；不要把配置文件放在静态资源目录。

打开周报或月报页面：

1. 单份起草：填写或智能选择报告周期，提供真实岗位、任务和工作素材，生成可编辑草稿。
2. AI 补全：查询历史缺报，选择需要的周期，逐份生成草稿。历史查询失败时不猜测缺报。
3. 生成中可以停止；已生成部分保留在当前浏览器。账号和学校之间的草稿独立保存。
4. 核对内容、日期和学校栏目，补充真实细节后导入编辑器，明确确认才会提交到习讯云。AI 生成接口本身不提交报告。

信息不足时内容会提示待补充；不能把生成文字直接当成真实工作事实。工作素材和当前报告周期会发送给部署者配置的 AI 服务，使用前应了解该服务的数据处理政策。服务端不把 AI 密钥、地址和模型返回给浏览器，只提供配置是否就绪的状态。

## 配置邮件提醒

在服务端配置：

```dotenv
SMTP_HOST=
SMTP_PORT=465
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_FROM=
```

使用你自己的 SMTP 服务和密码或授权码。本地配置在每次发送时读取；修改进程环境变量时需要重新启动服务。验证码发送和失败通知使用同一服务，账号密码不进入浏览器。

在“账号”页面的“签到提醒邮箱”中输入接收地址，完成人机验证并接收验证码。验证码仅对申请它的用户和邮箱有效，验证后才能开启提醒。可以暂停、更换或解除绑定；更换邮箱会使旧地址尚未发送的通知失效。

提醒针对最终失败和提交结果经复核仍无法确认的执行。提交结果待复核期间不会立即发失败邮件；通知队列持久化保存，单次执行最多创建一条通知事件。SMTP 已明确接收或发送结果不确定时，不自动重复发送同一封邮件。邮件问题不会触发重新签到。

## 更新已有部署

1. 停止旧服务并备份自己的数据库和本地配置，保留加密凭证文件。
2. 安装锁定的前端依赖、运行检查并重新构建前后端；不要用别人的数据库或 `.env` 覆盖已有数据。
3. 可选填写 AI 和 SMTP 配置，然后从原工作目录启动。启动时会补齐预检查、执行复核和邮件队列表及必要字段。
4. 查看健康接口与已有任务，核对执行状态。服务停止期间错过的时刻不会补签；自动执行仍需部署服务器持续运行。

源码发布前运行仓库范围检查、测试和秘密扫描。不要发布 `.env`、数据库及其 WAL/SHM 文件、密钥、日志、截图、构建产物或含凭证的压缩包。可选服务未配置时，普通签到和手动报告功能仍可使用。
